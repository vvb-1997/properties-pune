# Pune Home Hunt Dashboard

Open `index.html` in a browser. No build step. Needs internet only for charts, map tiles and map pins (CDN).

- **Add properties** on the Properties tab. Data is saved in this browser (localStorage). Use **Export JSON** regularly as backup, and **Import JSON** to restore or move to another device.
- **Market data** lives in `data/localities.js`. The figures are estimates, not live-verified. Update `rateMin`, `rateMax`, `rateAvg` (Rs per sq ft of saleable area) from portals and registered sale deeds.
- **Buildings and offerings**: one building holds several offerings (for example 2 BHK and 3 BHK), each with its own price, carpet, saleable area and negotiation room. Status, possession, RERA, broker, location and all ratings belong to the building. The table shows one row per offering. Clone duplicates an offering inside the same building. Old flat data is migrated automatically on load (one offering per building). Export JSON is version 2; version 1 files still import.
- **Sample properties** in `data/properties.js` are placeholders shown on first load. Delete them in the dashboard.
- **Scoring**: rate each property 1-5 on the criteria. Must-have items (water, power, waterlogging, RERA) rated 1-2 flag a deal-breaker. Adjust weights with "Score weights".
- **vs market** compares price per saleable sq ft (carpet x 1.3 if saleable area is not entered) with the locality range.

## Server (optional)
`node server.js`, then open http://localhost:8765. Every add, edit, delete or import is also written to `data/properties.js` (the browser's copy overwrites the file, last write wins). A fresh browser loads from that file. Set `HOST=0.0.0.0` to use it from a phone on the same Wi-Fi; there is no auth, so only on a trusted network. Opening `index.html` directly still works, without file sync.

## Dark mode, full-screen map, nearby, files
- **Dark mode**: toggle button in the header. Choice is kept in localStorage (`pune_theme`); first visit follows the system setting.
- **Full-screen map**: button on the Map tab (Esc exits).
- **Nearby**: "Nearby" button on each property row lists the 5 closest schools, hospitals, malls and parks/gardens (1/2/3/5 km), and can show them on the map. Data comes from OpenStreetMap via the public Overpass API, so coverage varies. **Privacy**: clicking Nearby sends the property's coordinates (or its locality centre if none are set) to overpass-api.de, and to overpass.kumi.systems if the first fails. Nothing is sent otherwise. Results are cached in the browser (`pune_nearby_v1`); Refresh re-fetches. It does not change scores.
- **Files tab** (needs `node server.js`): upload pdf, png, jpg, webp, gif, doc(x), xls(x), txt, csv up to 25 MB, optionally tagged to a building and to any of its offerings (none ticked = shared by all offerings; use Tag to change it later). Files are stored in `files/` (random names, list in `files/index.json`). Open shows pdf, images, txt, csv, xls(x) and docx in an in-page pop-up (`.doc` is download only; Office viewers load from a CDN, so they need internet). Upload rejects a file whose header bytes do not match its extension (400); the viewer re-checks. Deleting a building keeps its files, shown as "(deleted building)". Export JSON does **not** include files. No auth: with `HOST=0.0.0.0` anyone on the LAN can read and upload files.

## Auto-ratings (suggestions)
`node scripts/autorate.js <buildingId|--all> [--refresh] [--free]` rates schools, hospitals, malls, gardens, transport, commute, flood and safety from Google (Places, Routes, Elevation) and free map data (OpenStreetMap, Open-Meteo, OSRM). Results go to `p.auto` in `data/properties.js` and never overwrite your `p.scores`. `RATINGS.md` shows each suggestion with its reason and sources; `docs/RATING-SOURCES.md` lists sources, spend limits, rules and biases. Put `GOOGLE_API_KEY=...` in `.env` (git-ignored); without it only the free sources run. **Privacy**: building coordinates go to Google, Overpass, Open-Meteo and OSRM. **Cost**: capped per run and per month below Google's free allowances; also set a Google billing alert. Commute targets in `data/rating-config.js` are placeholders until you set your office. In the edit dialog of a saved building, each slider shows an `auto N` badge (hover for the reason), "Apply suggestions to unrated" fills only sliders still at 0, and "Run auto-rating" calls `POST /api/autorate/:id` (needs `node server.js`; one run at a time; about a minute; uses the saved coordinates; a building Google-rated within 30 days is skipped; `RATINGS.md` is only regenerated by the CLI). Dashboard saves keep the newer `p.auto` from `data/properties.js`, so the CLI can run while the server is up.
